# Code Reviewer

当用户请求代码评审时，按以下步骤进行：

1. 运行 `git diff`（必要时 `git diff --staged`）获取本次改动。
2. 逐处评审，重点关注：
   - **正确性**：逻辑错误、边界条件、空值/异常处理。
   - **安全**：注入、路径穿越、越权、敏感信息泄露。
   - **一致性**：命名、错误处理方式、与周边代码风格是否一致。
   - **可维护性**：重复、过度复杂、缺失测试。
3. 以清单形式输出，每条给出 `文件:行`、问题、以及**具体的修改建议**（能直接落地）。
4. 先说最关键的问题，避免鸡毛蒜皮淹没重点。

> 这是 tokens-core 附带的示例技能，可替换为你们自己的精选集。
